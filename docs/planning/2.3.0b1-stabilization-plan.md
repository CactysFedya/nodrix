# 2.3.0b1 stabilization plan and change register

This page is the release source of truth for the beta stabilization scope. It
separates delivered changes, release blockers, and later roadmap work.

## Release objective

Make the 2.3 workspace and operations line internally consistent and safe to
continue qualifying without claiming unfinished automation as shipped.

## Delivered by this change set

### Runtime and loader

- Cache a local Python file as one module per canonical path.
- Register the module in `sys.modules` before execution.
- Reuse class identity across multiple `module.py:Class` references.
- Remove failed imports from both caches.
- Add regression tests for dataclasses, repeated class loading, and recovery
  after a failed import.

### Release truth

- Set the public release to `2.3.0b1` in package, citation, CMake release
  string, compatibility pin, templates, tests, and release manifest.
- Correct public repository links to `CactysFedya/nodrix`.
- Replace stale README and changelog release headings.
- Add a release-metadata consistency test.

### Documentation

- Product principles and compatibility policy.
- EN/RU current release notes.
- EN/RU portable deployment guide.
- EN/RU FAST-LIVO2 semantic-mapping qualification page.
- Stabilization register and documentation scope.
- Release-critical documentation checker.

## Hardware evidence recorded, not generalized

The Raspberry Pi 5 integration demonstrates that Livox, FAST-LIVO2, camera,
Vision, managed applications, and semantic nodes can be assembled and started
through the current project. This is hardware smoke evidence only.

The release does not yet claim:

- correct non-empty semantic object output;
- confirmed `latest.ply` persistence;
- complete process-tree accounting;
- production endurance;
- one-command installation on a clean device.

## P0 release blockers

1. Confirm correct, non-empty semantic output.
2. Validate detector boxes, labels, class IDs, and reverse letterbox mapping.
3. Validate calibration direction, frames, and temporal skew.
4. Confirm `/Laser_map` reception and atomic `latest.ply` persistence.
5. Diagnose duplicate Livox nodes/processes.
6. Confirm graceful shutdown and repeatable restart.
7. Run the focused and full test suites from built artifacts.
8. Build EN and RU documentation with warnings treated as errors.

## P1 operations backlog

- Toolchain and virtual-environment isolation.
- Live build output and actionable failure summaries.
- Safe process-group ownership instead of broad `pkill -f`.
- Source manager, source lock, offline cache, and provenance.
- Resource-aware CMake/colcon build profiles.
- Patch create/verify/apply/status operations.
- Static verification of ROS packages, executables, launch files, libraries,
  and install-space outputs.
- Project discovery, default environment, shell completion, and environment
  diagnostics.
- Process-tree CPU/RSS and shutdown-state classification.
- Built-in stream inspection or a packaged viewer.

## P1 documentation backlog

- Complete Python Node SDK.
- Provider Developer Kit and contract-test tutorial.
- Native plugin SDK.
- Tested offline bundle workflow.
- ROS 2 QoS, TF2, services/actions, and rosbag guides.
- Capability and performance matrices.
- Troubleshooting pages backed by qualification tests.

## Target portable workflow

The intended future interface is:

```bash
plyctl project create ...
plyctl setup
plyctl configure robot
plyctl verify
plyctl run semantic-mapping
plyctl top
```

In `2.3.0b1`, this remains a target. Current deployment uses pinned source,
project scripts, existing finite workflows, and explicit verification.

## Definition of done

The beta may be tagged after:

- version and public metadata are consistent;
- local module identity tests pass;
- the full project test matrix passes;
- both documentation languages build without warnings;
- the source branch installs on Linux ARM64 without copying macOS artifacts;
- the known-good Raspberry Pi environment remains available for rollback.
