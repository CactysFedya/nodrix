# Nodrix Viewer: просмотр видеопотока

`nodrix-viewer` — отдельная программа для вывода видеопотока с минимальной
добавочной задержкой. Она не является обязательной нодой pipeline: ноутбук
можно подключить или отключить в любой момент, а камера и детектор продолжат
работать на устройстве.

## Установка

```bash
pip install "nodrix[viewer]"
```

## Запуск по имени stream

На устройстве:

```bash
nodrix run
```

На ноутбуке:

```bash
nodrix stream list
nodrix-viewer /camera/front/preview --fps 30
```

## Запуск по IP-адресу

Когда multicast discovery заблокирован:

```bash
nodrix-viewer \
  nodrix://192.168.1.50:7420/camera/front/preview \
  --fps 30
```

Здесь один позиционный параметр одновременно заменяет отдельные `--path` и
`--address`: Nodrix сам определяет вид источника.

## Другие источники

```bash
nodrix-viewer 0
nodrix-viewer /dev/video0
nodrix-viewer ./video.mp4
nodrix-viewer rtsp://192.168.1.20/live
nodrix-viewer http://192.168.1.20/mjpeg
```

## Параметры

```text
--fps 30                 ограничить частоту отображения
--fullscreen             полноэкранный режим
--scale 0.5              масштаб окна
--no-overlay             скрыть служебную информацию
--receive-buffer-kb 128  размер TCP receive buffer
--headless               работать без окна
--max-frames 300         завершить после N кадров
--json-stats             вывести статистику JSON
```

Клавиши:

```text
Q или Esc  закрыть
S          сохранить текущий кадр
```

## Что показывает overlay

- входной FPS;
- фактический FPS вывода;
- разрешение;
- sequence сообщения;
- число кадров, заменённых более свежими;
- оценку задержки;
- имя или адрес источника.

Для корректной задержки часы двух устройств должны быть синхронизированы через
NTP/PTP. Без синхронизации будет показано `latency n/a`.

## Почему поток не накапливает задержку

Viewer запрашивает у publisher:

```text
capacity: 1
policy: latest
```

Отдельный поток постоянно читает socket. Если окно ещё не успело показать
предыдущий кадр, он заменяется новым. Таким образом viewer пропускает кадры, но
не воспроизводит устаревшую очередь.

Полностью нулевая задержка невозможна: остаются захват, кодирование, сеть,
декодирование и вывод монитором. Цель Nodrix Viewer — убрать лишние очереди и
всегда показывать наиболее свежий доступный кадр.

## Оптимальная схема

```text
Camera raw Frame
├── zero-copy → Detector / Tracker
└── JPEG/H.264 encoder → network stream → Nodrix Viewer
```

Сырой кадр не нужно сначала сжимать и потом подавать в детектор. Компрессия
добавляется только в независимую сетевую ветку.

В Nodrix 0.6.0 внутри графа готов JPEG encoder. RTSP/H.264 адрес viewer может
открыть через OpenCV. Нативный H.264/H.265 encoder и декодирование отдельных
Nodrix access units запланированы для Media Pack следующей версии.
