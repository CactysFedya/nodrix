# Plyctl 2.3.0b1: стабилизация beta

`2.3.0b1` — стабилизационный релиз линии Workspace и Operations. Он не
переносит робототехнические алгоритмы в Core и не объявляет текущий
semantic-mapping prototype готовым к production; он остаётся экспериментальным.

## Что входит

- Кэширование локальных `module.py:Class` modules по canonical path.
- Регистрация module в `sys.modules` до выполнения кода. Это исправляет
  проблемы dataclass и различную identity классов, когда несколько nodes
  загружаются из одного файла.
- Очистка module cache и `sys.modules` после неуспешного импорта.
- Единая версия в Python package, CMake, compatibility package, citation,
  release manifest, tests, README и документации.
- Исправленные ссылки на настоящий репозиторий.
- Двуязычные принципы, реестр стабилизации, инструкция переноса на другое
  устройство, qualification notes для semantic mapping и release notes.
- Проверка критической документации.

## Hardware evidence

Интеграция запускалась на Raspberry Pi 5 с Ubuntu 24.04 ARM64 и ROS 2 Jazzy.
Livox LiDAR/IMU, FAST-LIVO2, RTSP-камера, native NCNN detector, tracker,
managed applications и semantic pipeline доходили до состояния ready.

Это hardware smoke qualification, но не универсальная production- или
performance-сертификация.

## Известные ограничения

- Semantic publishers существуют, но ненулевой результат
  `/semantic/object_points` ещё не квалифицирован.
- Создание `artifacts/maps/metric/latest.ply` должно быть подтверждено по
  реальному сообщению `/Laser_map` и health writer.
- Необходимо исследовать одинаковые имена нескольких Livox nodes.
- Source manager, resource-aware build, patch manager, полные process-tree
  metrics и конечные команды `plyctl setup/verify` остаются в backlog.
- Semantic prototype пока содержит project-local contracts и `core.any`.

## Обновление

Используйте точный commit или wheel. Нельзя переносить native wheel, собранный
на macOS, на Linux ARM64. Сборка должна выполняться на целевой платформе либо
в квалифицированном Linux ARM64 CI.

После установки:

```bash
plyctl --version
python -m pytest \
  tests/test_registry_file_module_cache.py \
  tests/test_release_metadata_consistency.py -q
```

## Совместимость

Сохраняются import и CLI alias `nodrix`, manifest aliases 2.x, provider
compatibility paths, native ABI, записи `.ndrx` и run-каталог `.nodrix/`.
