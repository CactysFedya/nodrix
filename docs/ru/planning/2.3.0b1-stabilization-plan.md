# План стабилизации и общий журнал 2.3.0b1

Эта страница — единый источник правды по объёму beta stabilization. Она
разделяет выполненные изменения, release blockers и последующий roadmap.

## Цель релиза

Сделать линию Workspace и Operations 2.3 внутренне согласованной и безопасной
для дальнейшей qualification, не объявляя незавершённую автоматизацию готовой.

## Что реально входит в этот change set

### Runtime и loader

- Один module object для локального Python-файла по canonical path.
- Регистрация module в `sys.modules` до выполнения.
- Одинаковая identity классов для нескольких `module.py:Class` references.
- Очистка cache и `sys.modules` после неуспешного импорта.
- Regression tests для dataclass, повторной загрузки классов и восстановления
  после failed import.

### Достоверность релиза

- Версия `2.3.0b1` в package, citation, CMake release string, compatibility pin,
  templates, tests и release manifest.
- Исправление публичных ссылок на `CactysFedya/nodrix`.
- Обновление устаревших заголовков README и CHANGELOG.
- Тест согласованности release metadata.

### Документация

- Нормативные принципы и политика совместимости.
- Текущие release notes EN/RU.
- Инструкция переноса на другое устройство EN/RU.
- Qualification page FAST-LIVO2 semantic mapping EN/RU.
- Реестр стабилизации и документационный scope.
- Проверка критической документации.

## Какое hardware evidence фиксируется

Проверка Raspberry Pi 5 показывает, что Livox, FAST-LIVO2, камера, Vision,
managed applications и semantic nodes могут быть собраны и запущены в текущем
проекте. Это hardware smoke evidence, а не production certification.

Релиз пока не обещает:

- корректный ненулевой semantic object output;
- подтверждённое сохранение `latest.ply`;
- полный process-tree accounting;
- длительную безотказную работу;
- установку на чистом устройстве одной готовой командой.

## P0 — блокирующие задачи

1. Получить корректный ненулевой semantic output.
2. Проверить detector boxes, labels, class IDs и reverse letterbox mapping.
3. Проверить направление calibration, frames и temporal skew.
4. Подтвердить получение `/Laser_map` и атомарную запись `latest.ply`.
5. Разобраться с дублирующимися Livox nodes/processes.
6. Подтвердить graceful shutdown и повторный restart.
7. Запустить focused и full tests из собранных artifacts.
8. Собрать документацию EN/RU с превращением warnings в ошибки.

## P1 — backlog Operations

- Изоляция toolchain и virtual environment.
- Live-вывод build и понятное резюме ошибки.
- Владение process group вместо широкого `pkill -f`.
- Source manager, source lock, offline cache и provenance.
- Resource-aware CMake/colcon profiles.
- Patch create/verify/apply/status operations.
- Статическая проверка ROS packages, executables, launch files, libraries и
  install-space outputs.
- Project discovery, default environment, completion и environment doctor.
- Process-tree CPU/RSS и классификация shutdown.
- Встроенный stream inspection или поставляемый viewer.

## P1 — backlog документации

- Генерируемый CLI и schema reference.
- Полный Python Node SDK.
- Provider Developer Kit и contract-test tutorial.
- Native plugin SDK.
- Проверенный offline bundle workflow.
- ROS 2 QoS, TF2, services/actions и rosbag guides.
- Capability и performance matrices.
- Troubleshooting, основанный на qualification tests.

## Целевой переносимый workflow

Планируемый конечный интерфейс:

```bash
plyctl project create ...
plyctl setup
plyctl configure robot
plyctl verify
plyctl run semantic-mapping
plyctl top
```

В `2.3.0b1` это остаётся целью. Текущий перенос выполняется через pinned source,
project scripts, существующие finite workflows и явную проверку.

## Definition of done

Beta можно тегировать после того, как:

- версия и публичная metadata согласованы;
- tests module identity проходят;
- проходит полная test matrix;
- обе версии документации собираются без warnings;
- source branch устанавливается на Linux ARM64 без копирования macOS artifacts;
- известное рабочее окружение Raspberry Pi сохранено для rollback.
