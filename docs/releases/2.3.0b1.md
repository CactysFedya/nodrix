# Plyctl 2.3.0b1: beta stabilization

`2.3.0b1` is a stabilization release for the workspace and operations line.
It does not move robotics algorithms into Core and does not declare the current
semantic-mapping prototype production-ready; it remains experimental.

## Included

- Stable, canonical-path caching for local `module.py:Class` nodes.
- Registration in `sys.modules` before module execution, which fixes dataclass
  and class-identity failures when several nodes come from one file.
- Failed local imports are removed from both the module cache and
  `sys.modules`.
- Consistent release metadata across Python packaging, CMake, compatibility
  metadata, citation, release manifest, tests, README, and documentation.
- Correct repository URLs.
- Bilingual principles, stabilization register, portable deployment guide,
  semantic-mapping qualification notes, and current release notes.
- Release-critical documentation checks.

## Hardware evidence

The integration was exercised on Raspberry Pi 5 with Ubuntu 24.04 ARM64 and
ROS 2 Jazzy. Livox LiDAR/IMU, FAST-LIVO2, RTSP camera, native NCNN detection,
tracking, managed applications, and the semantic pipeline reached their ready
states.

This evidence is a hardware smoke qualification, not a universal performance
or production certification.

## Known limitations

- Semantic `PointCloud2` publishers exist, but a non-empty
  `/semantic/object_points` result is not yet qualified.
- Persistence of `artifacts/maps/metric/latest.ply` still requires a confirmed
  `/Laser_map` message and writer evidence.
- Duplicate Livox node names must be investigated.
- Source management, resource-aware builds, patch management, complete
  process-tree telemetry, and the final `plyctl setup/verify` interface remain
  backlog items.
- The semantic prototype still contains project-local contracts and should
  migrate away from `core.any`.

## Upgrade

Pin the exact source commit or install an exact wheel. Do not copy a macOS
native wheel to Linux ARM64. Build on the target platform or use a qualified
Linux ARM64 CI artifact.

After installation:

```bash
plyctl --version
python -m pytest \
  tests/test_registry_file_module_cache.py \
  tests/test_release_metadata_consistency.py -q
```

## Compatibility

The `nodrix` import and CLI alias, 2.x manifest aliases, provider compatibility
paths, native ABI names, `.ndrx` recordings, and `.nodrix/` run paths remain
supported.
